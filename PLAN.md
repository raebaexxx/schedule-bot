# План: Telegram-бот с расписанием БА-231 (7 семестр, 2026/2027)

> Источник: `~/Загрузки/4curs2026.pdf` (расписание 4 курса ЕТИ МГТУ «СТАНКИН»).
> Решения пользователя: только группа **БА-231**; код **с нуля**; фильтр по датам;
> обновление семестра — **парсер PDF**.
> **ВАЖНО: эталон данных — сам PDF.** Старый `schedule_data.py` эталоном НЕ является.
> Точность: два независимых метода извлечения (координатный bbox + layout-текст)
> с перекрёстной сверкой + полная ручная сверка всех занятий.

## Формат данных
Занятие:
```json
{
  "time": "08:30-10:05",
  "kind": "лек., пр.",
  "subject": "Бережливое производство",
  "teacher": "ЗАМЛЕЛАЯ А.Т.",
  "room": "204",
  "link": "https://...",
  "ranges": [["2026-09-07", "2026-09-28"]],
  "exact_dates": ["2026-11-16"]
}
```
- Активно на дату D ⇔ D в одном из `ranges` или в `exact_dates`.
- Семестр: 01.09.2026–28.12.2026 (сверено по PDF: занятия с 01.09 по 23.12).
- Вне семестра / воскресенье → «Нет занятий».

## Этапы

### 1. Подготовка сырых выгрузок PDF  [✓ начало сделано]
- `pdftotext -layout` → `data/layout.txt`
- `pdftotext -bbox-layout` → `data/bbox.xml` (слова с координатами)

### 2. Парсер `scripts/parse_pdf.py`
Подход (bbox — основной, layout — контрольный):
1. Из bbox.xml: вырезать колонку БА-231 по X-диапазону (левая колонка после колонки времени/дней).
2. Группировать слова по Y-строкам в пределах временных слотов (08.30-10.05, 10.15-11.50,
   12.20-13.55, 14.05-15.40, ...) и маркеров дней (ПНД, ВТР, СРД, ЧТВ, ПТН, СБТ).
3. Парсить блоки занятий: тип (лек./пр./лаб./Проект), название, ФИО, аудитория,
   даты (`с DD.MM по DD.MM`, `DD.MM`, `DD.MM и DD.MM`), ссылки my.mts-link.ru.
4. Восстановить разорванные переносами строки названия предметов.

### 3. Валидация точности (БЕЗ старого schedule_data.py как эталона)
- **Метод A (основной):** bbox-колонка → занятия.
- **Метод B (контроль):** layout-текст → независимый сбор (regex по ФИО/датам/слотам).
- Сверка A vs B: количество занятий на слот, ФИО, аудитории, диапазоны дат — расхождения разбираются вручную по layout.txt.
- **Ручная проверка:** полный проход по layout.txt против сгенерированного JSON.
- Sanity-чеки: даты в [01.09.2026 .. 28.12.2026]; время слотов из известного списка;
  каждое занятие имеет ФИО и аудиторию; ссылки только у онлайн-пар (вирт. ауд.).

### 4. Бот
- `/start` — меню: Сегодня / Завтра / По дням / Вся неделя
- `/today`, `/tomorrow`, `/date DD.MM`, `/week`, `/monday`..`/saturday`
- Фильтрация по дате; пустой день → «Нет занятий»
- Неделя: 6 дней от понедельника текущей недели, каждый отфильтрован

### 5. Тесты
- test_parser: сборка из фикстуры layout-текста, regex дат, склейка переносов
- test_filter: границы диапазонов, одиночные даты, воскресенье, вне семестра

### 6. Запуск
- `.env` с BOT_TOKEN (перенести из старого .env), smoke-тест вживую.

## Риски
- Excel-PDF рвёт строки → митигируется bbox-подходом, двойным извлечением и ручной сверкой.
- Парсер нужен раз в семестр → простота важнее универсальности, формат выгрузки стабилен.

## Итог реализации (2026-08-31)

### Парсер (`scripts/parse_pdf.py`) — фактический алгоритм
1. `pdftotext -bbox-layout` → слова с координатами.
2. Слова кластеризуются в **визуальные строки** по Y (Excel-выгрузка рвёт строку
   на несколько `<line>`; tol 1pt).
3. Колонка БА-231: слова с x∈[113, 206.5) (границы сняты с заголовков таблицы).
4. Якоря: маркеры дней (ПНД/…) и **26 меток времени** (некоторые слиты со
   строкой занятия — извлекаются на уровне слов).
5. **Сегментация занятий глобальна** (по маркерам типа лек./пр./лаб./Проект) —
   занятие никогда не разрезается между строками таблицы.
6. **DP-распределение** занятий по 26 строкам: стоимость строки =
   Σ|центр занятия − якорь| + |центр диапазона строки − якорь| (метка времени
   в Excel центрирована в своей строке). Пустые строки допустимы.
7. Многопроходный разбор занятия: тип → ФИО → аудитория → ссылка → даты
   (диапазоны «с X по Y», одиночные «DD.MM», пары «DD.MM и DD.MM») → предмет.
   Порядок токенов не важен (переносы строк в Excel-ячейке).
8. Подписи под таблицей («Начальник УМО …») отфильтровываются.

### Валидация (эталон — PDF)
- **Метод B**: каждое занятие проверено по независимому `pdftotext -layout`
  срезу колонки БА (ФИО, аудитория, даты, предмет) — все 43 подтверждены.
- **Ручная сверка**: все 43 занятия по всем 6 дням совпали с PDF
  (предметы, типы, ФИО, аудитории, даты; ЧТ 15:50 и суббота у БА-231 пустые).
- Проверено: у ВТ «Бережливое производство» в PDF пустая ячейка аудитории —
  это особенность источника, не ошибка парсера (`room: ""`).
- Sanity-чеки: даты в семестре 01.09–28.12.2026, полнота полей.

### Тесты
28 тестов (unittest): разбор дат/ФИО/аудиторий/ссылок, регрессия полного
пайплайна по `data/bbox.xml`, фильтры дат (границы диапазонов, точные даты,
воскресенье, конец семестра), разрез длинных сообщений.
Запуск: `.venv/bin/python -m unittest discover -s tests`

### Бот
- `/start` (меню: Сегодня / Завтра / По дням / Вся неделя), `/today`, `/tomorrow`,
  `/week`, `/date DD.MM`, `/monday`…`/friday`, `/help`.
- **Суббота убрана из бота** (у БА-231 занятий нет): кнопки, команды и неделя —
  5 дней; данные в JSON сохранены полностью.
- **Номер пары цифрой** перед временем слота (1–5, по сетке звонков; хранится
  в данных, поле `pair`, заполняет парсер).
- Фильтрация по датам; «Нет занятий» на пустые даты; воскресенье обрабатывается.
- Часовой пояс Europe/Moscow; длинная неделя режется на части ≤3900 символов.
- Запуск: `.venv/bin/python bot.py` (нужен `BOT_TOKEN` в `.env`).
- Ctrl+C: SIGINT → aiogram корректно останавливает polling, процесс завершается.
